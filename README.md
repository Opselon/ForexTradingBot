# ForexTradingBot

Production-ready trading bot platform with **multi-database support** — pick
**PostgreSQL**, **SQLite** or **SQL Server** on first startup. Runs fully
containerized (PostgreSQL + Redis + API) or natively on Windows / Linux / macOS.

---

## Quick install — one command

### Linux / macOS

```bash
curl -fsSL https://raw.githubusercontent.com/Opselon/ForexTradingBot/main/install.sh | bash
```

### Windows (PowerShell)

```powershell
irm https://raw.githubusercontent.com/Opselon/ForexTradingBot/main/install.ps1 | iex
```

Both scripts are interactive but safe to re-run (fully idempotent):

| Option | What happens |
|--------|--------------|
| **1) Docker** (recommended) | Clones the repo, generates a database password into `.env`, builds the image, starts **PostgreSQL + Redis + API**, waits for `/health` and prints the result. Nothing else to configure. |
| **2) Normal** | Installs the **.NET 9 SDK** if missing, builds, then starts the app. **On first startup the app itself asks which database you want** (see below) and remembers the answer. |

## First-run database wizard

The first time the app starts without a configured database, it prints:

```
  ╔══════════════════════════════════════════════════════╗
  ║        ForexTradingBot — First-Run Setup             ║
  ║   پایگاه داده‌ی مورد نظر خود را انتخاب کنید           ║
  ╚══════════════════════════════════════════════════════╝

   1) SQLite      — سریع‌ترین، بدون نصب، فایل محلی
   2) PostgreSQL  — پیشنهادی برای سرور و production
   3) SQL Server  — مناسب محیط‌های ویندوزی موجود

  انتخاب شما [1/2/3] (پیش‌فرض: 1):
```

Your choice (provider + connection string, password entered hidden) is saved to
`appsettings.Local.json` and is picked up on every later start — the wizard only
appears once.

### Non-interactive environments (Docker, CI, systemd)

Set environment variables instead; the wizard is skipped automatically:

```bash
DatabaseProvider=Postgres   # SqlServer | Postgres | Sqlite  (aliases accepted: pg, postgresql, sql-lite, …)
ConnectionStrings__DefaultConnection="Host=db;Database=forexbot;Username=app;Password=…"
```

With no variables at all, the app falls back to **SQLite** and starts anyway —
no configuration is required to get a healthy process.

## Supported databases

| Provider | Schema creation | Hangfire storage | Notes |
|----------|-----------------|------------------|-------|
| **SQLite** | EF `GenerateCreateScript` (types translated) | `Hangfire.Storage.SQLite` | Zero setup — single file |
| **PostgreSQL** | EF `GenerateCreateScript` (types translated) | `Hangfire.PostgreSql` | Auto-creates the database on first run |
| **SQL Server** | EF migrations (`MigrateAsync`) | SQL Server storage | Auto-creates the database via `master` |

The EF model is declared with SQL Server type names (`nvarchar(max)`,
`datetime2`, `uniqueidentifier`, `bit`, `decimal(18,8)`, `GETUTCDATE()`,
`WHERE [Col] IS NOT NULL`). Those are translated per-provider at schema-creation
time by `Infrastructure/Data/DatabaseProviderConfigurator.TranslateSchemaScript`,
so the same model works on all three engines.

## Docker

```bash
cp .env.example .env          # then edit values (or let install.sh generate them)
docker compose up -d --build
curl http://localhost:8080/health        # → {"status":"healthy",…}
```

Services: `forex-api` (:8080), `postgres:17` (:5432), `redis:7` (:6379).

```bash
docker compose logs -f forex-api   # logs
docker compose down                 # stop
docker compose down -v              # stop + wipe data
```

## Normal (native) install

```bash
# Linux / macOS
dotnet build -c Release
dotnet run --project WebAPI -c Release     # first run shows the DB wizard
# health: http://localhost:5000/health
```

```powershell
# Windows
dotnet build -c Release
dotnet run --project WebAPI -c Release
```

Requirements: .NET 9 SDK (the installer adds it automatically).

## Releases (CI)

Releases are published automatically by GitHub Actions
(`.github/workflows/release.yml`) whenever a version tag is pushed:

```bash
git tag v1.0.0
git push origin v1.0.0
```

That runs tests, then publishes:

* self-contained archives for `linux-x64`, `win-x64`, `osx-x64`, `osx-arm64`
* a container image to `ghcr.io/<owner>/<repo>:<version>` (plus `latest`)
* a GitHub Release with notes generated from commits since the previous tag

PRs and pushes to `main` are verified by `.github/workflows/ci.yml`
(build + tests + Docker smoke test against both PostgreSQL and SQLite).

## Security notes

* `.env` is git-ignored — never commit real tokens.
* Database passwords are auto-generated by the installer, never defaults.
* Telegram bot token is **optional**: the app starts and stays healthy without
  it; Telegram features are disabled and logged until you configure it.
